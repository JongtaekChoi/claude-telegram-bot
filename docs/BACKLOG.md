## 검증 빚

구현·커밋됐지만 실봇으로 확인하지 않은 것.

- [ ] **`personas[].dir` (6a)** — 임시 config 로 부팅·작업 감시까지는 확인했다(폴더 두 개에
      `.ctb-outbox`·`.ctb-jobs` 생성, 없는 `dir` 은 안 만들고 로그, 하위 폴더에 떨어진 작업 기록을
      감시가 회수). **실봇에서 볼 것:** `dir` 을 가진 방에서 `/sessions` 가 그 폴더 세션을 보여주는지
      (제일 조용히 깨지는 자리), `/jobs` 가 폴더 태그와 함께 전부 보여주는지, 이미지 마커가 그 방
      아웃박스에서 읽히는지, `/status`·`/help` 의 작업 폴더가 방마다 다른지, 없는 `dir` 방에서
      안내가 뜨는지, `ctb --chat <그 방>` 이 그 폴더에서 열리는지.
- [ ] **`/cron add` 가 적은 방으로만 결과가 가는지** — 코드·테스트는 끝났고 봇도 새로 떴다.
      **실봇에서 볼 것:** DM 에서 `/cron add` 한 작업의 결과가 **그 방에만** 오는지(예전엔 그룹에도
      떨어졌다), `/cron` 목록에 목적지가 뜨는지, 등록 확인 문구가 어디로 갈지 밝히는지.
      매분 작업은 실행당 $0.12 이므로 **확인 후 바로 `/cron rm`** 할 것.
- [ ] **포럼 상위 토픽 접수처** — 자동 판정이라 켤 것이 없다. **실봇에서 볼 것:** 봇유지보수
      상위 방(= "모두" 뷰)에서 말을 걸면 실행 대신 형제 토픽 버튼이 뜨는지, 고르면 그 토픽에서
      머리말 없이 돌고 답이 거기 남는지, 첨부·스크린샷이 따라가는지, 긴 로그를 붙여넣어 조각나도
      버튼이 **한 번만** 뜨는지, `[여기서 실행]`·`[안 보냄]` 이 각각 도는지/안 도는지, 토픽 방과
      DM 은 예전 그대로인지, `/status`·`/stop` 이 상위 방에서 여전히 즉시 동작하는지.
      ⚠️ **상위 방 뮤트(`/*`)를 먼저 풀어야 한다** — 뮤트 검사가 더 위에 있어서 뮤트된 방에서는
      이 게이트까지 오지 않는다. 임시 방편으로 걸어 둔 뮤트가 있으면 `*/` 로 푼다.
      **조용한 창(10분)도 같이 볼 것:** 버튼을 거쳐 한 번 돈 뒤 이어 말하면 **안 묻고 그냥 도는지**,
      그 방에서 20분 넘게 조용했다가 말하면 **다시 묻는지**, 형제 토픽으로 보낸 것은 상위 방의
      창을 열지 **않는지**(보낸 뒤 상위에 또 쓰면 다시 물어야 한다).
- [ ] **`/allow` (owner-admin 1·2단계)** — `state.allowedChatIds` 의 부팅 병합은 확인했다(그 키만
      있으면 화이트리스트가 채워지고, 없으면 스케줄러가 비활성 경고를 낸다). **실봇에서 볼 것:**
      DM 에서 `/allow` 목록에 출처 세 갈래가 제대로 뜨는지, 새 그룹을 `/allow <id>` 로 열면
      재시작 없이 바로 응답하는지, `[config]` 출신 제거가 안내로 막히는지, 본인 DM 제거가 막히는지,
      그룹에서 오너가 아닌 사람이 `/allow` 를 쳤을 때 **아무 일도 안 일어나는지**(에이전트 실행도
      포함해서).

- [ ] **잃어버린 스위트 복원** — `tests/` 골격은 섰고 0.5.0 이 건드린 곳은 다 덮었다(107건).
      아직 커버리지가 0 인 것들: **persona(52) · memory(37) · sessions(17) · lock · title · pick ·
      compact-defer(12)** — 2026-09-02 에 스크래치패드와 함께 증발했다. 전부 **이미 배포된**
      코드라 급하진 않지만, 손대면 그때가 되살릴 때다. `tests/*.test.mjs` 에 같은 틀로 넣는다.

## 안 하기로 한 것

되살아나는 걸 막으려고 남긴다.

- **그룹 멘션 게이팅** — 멘션·리플라이일 때만 응답하는 방식. `allowedChatId` 가 이미 방 단위로
  막고, 그룹에 있는 사람은 그 방을 통과한 것으로 본다.
  → [design/group-chat-multi-user.md](design/group-chat-multi-user.md)
- **그룹 안에서 사람별 세션 분리** — 방 단위 분리로 확정. 같은 문서의 "열린 질문" 참고.
- **로컬 `ctb` 락을 머신 전역으로 두기** — 0.4.13 에서 방 단위로 뒤집었다. 같은 문서 참고.
- **`/panel` 다중 페르소나 라운드테이블** — 프로토타입까지 갔다가 폐기.
- **메시지를 지우면 중지** — 봇은 삭제를 알 수 없다. Bot API 에 일반 채팅의 삭제 업데이트가
  없다(비즈니스 계정 연결의 `deleted_business_messages` 뿐이라 해당 없음). 수정(`edited_message`)
  은 받을 수 있으니 그쪽으로 간다.
- **봇이 `config.json` 을 쓰는 것** — "어드민 방에서 설정을 고친다"로 검토. config 가 깨지면
  부팅 `JSON.parse` 에 보호가 없어 크래시 루프에 빠지고, 원격 관리하려던 기능이 실패할 때 SSH 를
  유일한 복구 수단으로 만든다. → [design/owner-admin.md](design/owner-admin.md)
- **어드민 "방" (`allowedChatId` 첫 항목)** — 권한 경계가 배열 순서에 실리고, 그룹이면 전원이
  어드민이 된다. 사람(`msg.from.id`) 으로 가른다. 같은 문서 참고.
- **방 키 단위 config 맵(`rooms`)** — 토픽 `threadId` 를 사전에 알 수 없고, 방별 선택이 state 와
  이중화되며, General 토픽의 방 키가 그룹 ID 와 같아 한 키에 두 의미가 겹친다.
  → [design/room-personas.md](design/room-personas.md) 의 "안 하기로 한 것"
