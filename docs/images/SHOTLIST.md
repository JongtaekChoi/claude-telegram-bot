# README 스크린샷 촬영 목록

README(영/국문) 상단의 "What it looks like" / "실제 화면" 자리에 넣을 이미지들. 지금은 두 README에
HTML 주석(`<!-- SCREENSHOTS -->`)으로 자리만 잡혀 있고, 파일이 들어오면 주석을 풀면 된다.

촬영은 **텔레그램 앱에서 직접** 해야 한다. 봇 화면이 곧 제품이라 목업은 의미가 없다.

## 총 5장 — 영문 4장 + 한글 1장

영문 4장을 양쪽 README가 공유하고, 한국어 README의 첫 장(히어로)만 한글로 따로 찍는다.

이유: 영문 README에 한글 스크린샷이 있으면 해외 사용자는 봇 답변을 읽을 수 없고 "한국 프로젝트"
신호로 읽힌다. 반대 방향은 문제가 안 된다. 그래서 기본은 영문으로 깔고, 임팩트가 가장 큰
첫 장만 한 벌 더 찍는다.

| 파일 | 쓰이는 곳 |
|---|---|
| `01-chat.png` | README.md |
| `01-chat.ko.png` | README.ko.md |
| `02-plan.png` · `03-provider.png` · `04-notes.png` | 양쪽 공유 |

## 촬영 순서

영문 화면을 먼저 몰아 찍고, 마지막에 한글 한 장을 추가하는 게 재시작 횟수가 적다.

1. config 에 `"lang": "en"` 추가 → `/restart`
2. **프롬프트를 영어로 써서** `01` ~ `04` 촬영 (Claude 답변은 내가 쓴 언어를 따라간다)
3. `"lang"` 원복 → `/restart`
4. 한국어로 `01-chat.ko.png` 한 장 더 촬영

## 공통 규칙

- **토큰·chatId·실제 경로가 화면에 없는지 확인.** 특히 `01` 에서 봇 답변에 `/Users/…` 경로가
  섞여 나오면 가리거나 다시 찍을 것. `/status` 화면은 환경이 다 드러나서 목록에서 아예 뺐다.
- **다크 모드로 5장 통일.** 하나만 라이트면 티가 많이 난다.
- 상태바(시계·배터리·통신사)는 잘라내는 편이 깔끔하다.
- PNG, 폭 1200px 이하로 줄여서 커밋 (레포가 무거워지지 않게).
- 파일명은 위에 지정된 이름 그대로.

## 각 장 상세

### `01-chat.png` / `01-chat.ko.png` — 핵심 셀링 이미지

실제로 일을 시키고, **지시와 결과가 한 화면에** 들어오게 스크롤을 맞춰 캡처한다.

```
run the tests and summarize any failures
테스트 돌려보고 실패한 거 있으면 요약해줘
```

답변이 길어 잘리는 건 괜찮지만 **내 지시는 반드시 화면에 들어가야** 한다 —
"메시지 하나가 실제 작업이 된다"가 이 장의 전부다. 결과가 짧고 명확한 작업(테스트 통과/실패
요약)이 가장 잘 맞는다.

### `02-plan.png` — 이 봇의 차별점

```
/plan add a license badge to the README
```

계획이 오고 **✅ Proceed / ❌ Cancel** 버튼이 붙은 상태에서, **누르기 전에** 캡처.

비교표에는 "작업별 승인 버튼: 없음"이라고 적혀 있지만 `/plan` 이 사실상 그 역할을 한다.
글로만 있으면 전달되지 않는 부분이라 이미지가 필요하다.

### `03-provider.png` — 0.4.9 에서 추가된 버튼 UI

`/provider` 한 줄이면 끝. `claude` · `codex` · `Config default` 버튼이 뜨고 현재 것에 ✅ 가
붙은 화면을, 역시 **누르기 전에** 캡처.

### `04-notes.png` — 설명만으로는 안 와닿는 기능

```
// try splitting sessions per group chat later
```

봇이 아무 답도 하지 않고 👀 리액션만 붙은 상태를 캡처.

**위쪽에 봇과의 정상 대화가 몇 줄 보이게** 잡을 것. 그래야 "원래는 답하는 봇인데 이것만
무시했다"가 대비돼서 읽힌다. `//` 메시지만 덩그러니 있으면 무엇을 보여주는 화면인지 알 수 없다.
이 장은 양쪽 README가 공유하므로 메모 내용도 영어로 쓴다.
